# Citus against MarkLogic's transaction guarantees

@use_case Development/UseCase/UC_Citus
@facet Store

Generated by `features/acid.feature` (2026-10-17) against the on-demand cluster on Vultr: PostgreSQL 17.11, Citus 14.2-1, pgvector 0.8.7; a coordinator and two workers on a vc2-2c-4gb each, over a Vultr VPC (slice 2).

| Scenario | Result |
|---|---|
| The record is spread over the workers, each datum whole on one, the vocabulary on every node | passed |
| A datum is one transaction: its document, text, vector and triples | passed |
| A datum that fails leaves nothing behind | passed |
| The eight competency questions answer as MarkLogic's do | passed |
| Inference sees its own transaction's writes and no other's | passed |
| Inference is never stale: new data and a new vocabulary are answered at once | passed |
| One transaction across two workers commits on both or on neither | passed |
| A two-phase commit whose worker crashes after PREPARE is finished by the coordinator | passed |
| A two-phase commit whose coordinator crashes after PREPARE commits nowhere | passed |
| A concurrent update is not lost | passed |
| A committed datum survives a crash of the worker that holds it | passed |
| A worker is added and removed while writes go on | passed |
